MSX against Spectrum measurements (0.95 to 0.100), as recovered from the machine they were run on.
File dates are kept from the originals.

scripts/msx50.py      MSX side: the original in msxsim/layoutsim, 50 Hz frames
                      (71,591 T), the port's front end (lockstep_spec.patch_front_end),
                      invulnerable, fire tapped. The BIOS time estimates are the
                      COST table near the top: (fixed T-states, T-states per byte).
                      Writes per second of play: [second, ticks, distance, stage].
scripts/specrun.py    Spectrum side, same keys and invulnerability; same rows,
                      and prints screens a second (not saved in the JSON).
scripts/playspeed.py  The earlier speed script whose 'plain' workload msx50.py
                      and specrun.py copy.
scripts/lag2.py       Spectrum input lag: press at a frame start, counted to the
                      frame whose displayed screen shows the ship moved, plus
                      (63 + y) / 312 for the beam. SEED selects the run.
scripts/lag.py        The same, before SEED was added (seed fixed at 7).
scripts/msx_lag2.py   MSX input lag (the only MSX lag script found): 24 presses,
scripts/msx_lag.py    PAL frames of 71,364 T, plain BIOS stubs, no front-end
                      patch, joystick; lag2 also logs when in the frame the
                      sprite table was written. No beam term, no 200-press runs.

data/L_*.json         610-second runs (stages 1-3) behind the 6.8 table:
                      L_msx (MSX), L_n100_fast/smooth (0.100),
                      L_f1smooth and L_f3fast (0.99a columns),
                      L_o99a_fast/smooth (0.99a measured again alongside 0.100),
                      and earlier 0.95/0.96 experiments.
data/cmp_*.json       325-second runs from the 0.95/0.96 work.
                      Stage lengths are the count of rows with each stage
                      number; no script for that step was found.

helpers_0.100/        The modules the scripts import, as in the 0.100 source
                      (paths as in the repository then). The scripts find the
                      repository from their own place, and need nem.rom, the
                      disassembly (not included) and a built nemesis.sna/.sym.
